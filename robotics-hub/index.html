How To Use This Guide

You are the engineer now. This guide is complete: every mission contains the full Python program, explained line by line. You do not need to search any website — the only link that leaves this page is the robot Build in Mission 1, which points to the official building instructions. (If you finish early and want bonus challenges, the Prime Lessons site has more — ask a parent.)

For each mission you follow the same 4-step loop you used when learning Python:

THE 4-STEP LOOP
✍️ 1. WRITE  (5–10 min) — Find the NEW LINES box in the mission. Copy those lines BY HAND into your Robot Lab Notebook. No copy-paste, no photos. Your brain remembers what your hand writes. (The gray "magic header" at the top of every program is always the same — memorize it once, then just write it from memory.)
🔮 2. PREDICT  (3 min) — Before you run anything, write what you think the robot will do — line by line. Be specific: which direction? How far? What sound? What will the sensor see?
▶️ 3. RUN  (10 min) — Type the whole program (header + new lines) into a new Python project in the SPIKE app and run it. Compare it with your prediction. If the robot did something different, find the line that surprised you. That surprise is where the learning lives.
🚀 4. EXTEND  (10 min) — Do the mission's EXTEND challenge: change ONE thing to make the robot do something new. Predict again before you run. Write what happened in your notebook.
HOUSE RULES
  • One mission per session. A session is 30–45 minutes, 2–3 times a week.
  • The 15-Minute Rule: stuck for 15 minutes? Re-read the mission's LINE BY LINE box slowly, then check the Troubleshooting section at the end of this guide.
  • Change one thing at a time. Always.
  • Keep your test robot built. Do not take it apart during this course.

The Magic Header — Memorize Once

Every program in this course starts with the same lines. They tell the hub which tools (motors, sensors, lights, sounds) your program may use. Copy this header by hand until you can write it from memory — then every mission gets shorter.

THE MAGIC HEADER — TOP OF EVERY PROGRAM
from hub import port, light_matrix, motion_sensor
from app import sound
import runloop
import motor_pair
import color_sensor
import color
import distance_sensor
import force_sensor

motor_pair.pair(motor_pair.PAIR_1, port.A, port.E)
  • What it means: port.A … port.F are the six plugs on the hub. This course always uses the same plugs: left drive motor → A, right drive motor → E, distance sensor → C, color sensor → F, force sensor → D. The last line pairs the two drive motors so they can work as a team.
  • The shape of every program: after the header comes async def main(): with your robot's steps inside it, and the very last line is always runloop.run(main()) which means "start!".
  • async / await: async def main(): means "these steps happen one at a time, in order." await in front of a step means "wait until this step finishes before going on." You don't need to understand it deeply yet — just always include them.
💡 Your first WRITE exercise: copy the magic header into your notebook right now, from the screen, by hand. Then close this guide and write it again from memory. Repeat until you can do it without peeking.

MISSION 2 — Wake Up the Hub

Goal: Make the hub show a letter, wait, and play a sound.

New commands in this mission: light_matrix.write, runloop.sleep_ms, sound.play.

THE PROGRAM — TYPE THIS INTO THE SPIKE APP
# magic header (write from memory!)
from hub import port, light_matrix, motion_sensor
from app import sound
import runloop
import motor_pair
import color_sensor
import color
import distance_sensor
import force_sensor

motor_pair.pair(motor_pair.PAIR_1, port.A, port.E)

async def main():
    await light_matrix.write('A')
    await runloop.sleep_ms(1000)
    await sound.play('Sport Whistle 1')

runloop.run(main())
  • await light_matrix.write('A') — scrolls the letter A across the hub's 5×5 lights. await = wait until the scrolling finishes.
  • await runloop.sleep_ms(1000) — do nothing for 1000 milliseconds (1 second).
  • await sound.play('Sport Whistle 1') — plays a built-in sound. The hub knows several: 'Sport Whistle 1', 'Sport Whistle 2', 'Male Jump 1'.
✍️ WRITE — The header comes from memory. Hand-copy only the 3 new lines inside main().
🔮 PREDICT — What will you see first — the letter or the sound? How long is the pause?
▶️ RUN — Compare. Did the letter scroll before the whistle?
🚀 EXTEND — Show the first letter of your name, wait 2 seconds, then play a different sound. Which lines changed?
MISSION 3 — Move Straight & Turn

Goal: Drive forward an exact distance, then make an exact 90° turn using the gyro sensor.

New commands: motor_pair.move_for_degrees, motor_pair.move, motor_pair.stop, motion_sensor.reset_yaw, motion_sensor.tilt_angles, runloop.until.

THE PROGRAM — TYPE THIS INTO THE SPIKE APP
# magic header (from memory)
from hub import port, light_matrix, motion_sensor
from app import sound
import runloop
import motor_pair
import color_sensor
import color
import distance_sensor
import force_sensor

motor_pair.pair(motor_pair.PAIR_1, port.A, port.E)

async def turn_right():
    motion_sensor.reset_yaw(0)
    motor_pair.move(motor_pair.PAIR_1, 100, velocity=200)
    await runloop.until(lambda: motion_sensor.tilt_angles()[0] <= -900)
    motor_pair.stop(motor_pair.PAIR_1)

async def main():
    await motor_pair.move_for_degrees(motor_pair.PAIR_1, 720, 0, velocity=300)
    await runloop.sleep_ms(500)
    await turn_right()

runloop.run(main())
  • await motor_pair.move_for_degrees(motor_pair.PAIR_1, 720, 0, velocity=300) — drive both motors 720 degrees of wheel turning. The 0 is steering: 0 = straight, 100 = spin right, -100 = spin left. velocity=300 is speed (degrees per second). await = wait until the driving finishes. 720° = 2 full wheel turns ≈ 55 cm with the big wheels.
  • motion_sensor.reset_yaw(0) — set the gyro's "which way am I facing" meter to zero, right now.
  • motor_pair.move(motor_pair.PAIR_1, 100, velocity=200) — start spinning right (steering 100). No await: it starts and the program keeps going immediately.
  • await runloop.until(lambda: motion_sensor.tilt_angles()[0] <= -900) — wait until the gyro says we turned 90°. tilt_angles()[0] is the turn angle in tenths of a degree, so 900 = 90°. Negative = right turn.
  • motor_pair.stop(motor_pair.PAIR_1) — stop both motors.
  • async def turn_right(): — you just taught the robot a brand-new command. await turn_right() uses it. (You know functions from Python!)
✍️ WRITE — Hand-copy turn_right() and the two driving lines in main().
🔮 PREDICT — How far will the robot drive? (Measure with a ruler after!) Which way does it turn — and how do you know it's 90°?
▶️ RUN — Measure the real distance. How close was your prediction?
🚀 EXTEND — Drive a perfect square and stop where you started. Plan on paper first: you need turn_right() four times and a loop. Hint: for side in range(4):
💡 Backward? If your robot drives backward, change velocity=300 to velocity=-300. The minus sign flips the direction.

Phase 2 — Sensors

Sensors are the robot's eyes and ears. A robot that uses sensors is 10× more reliable than one that just guesses — this is the biggest secret in robotics.

MISSION 4 — Parking Assistant

Goal: Drive toward a wall and stop 20 cm before hitting it.

New commands: distance_sensor.distance. New idea: a helper function that answers yes/no.

THE PROGRAM — TYPE THIS INTO THE SPIKE APP
# magic header (from memory) + pair line
# ...
def wall_close():
    d = distance_sensor.distance(port.C)   # millimeters, or None
    return d is not None and d < 200        # 200 mm = 20 cm

async def main():
    motor_pair.move(motor_pair.PAIR_1, 0, velocity=300)
    await runloop.until(wall_close)
    motor_pair.stop(motor_pair.PAIR_1)

runloop.run(main())
  • distance_sensor.distance(port.C) — how far is the nearest object, in millimeters. Returns None if nothing is in range.
  • def wall_close(): — a helper that returns True only when a wall is closer than 200 mm. The d is not None check keeps the program from crashing when the sensor sees nothing.
  • await runloop.until(wall_close) — wait here until the helper says True. This is the "wait for the wall" trick — memorize this pattern, you will use it in every phase.
✍️ WRITE — Hand-copy wall_close() and the three lines in main().
🔮 PREDICT — Exactly where will the robot stop? Which number decides it? What happens if you start it facing an empty room?
▶️ RUN — Test with a book as the wall. Measure the stopping distance with a ruler.
🚀 EXTEND — Change the stop distance to 10 cm. Then make it beep faster as the wall gets closer: 
async def main():
    while True:
        d = distance_sensor.distance(port.C)
        if d is None:
            d = 9999
        if d < 150:
            break
        motor_pair.move(motor_pair.PAIR_1, 0, velocity=300)
        await sound.play('Sport Whistle 1')
        await runloop.sleep_ms(d)   # far = long wait, close = short wait!
    motor_pair.stop(motor_pair.PAIR_1)

MISSION 6 — Press to Start

Goal: The robot drives only while you press the force sensor — a dead-man's switch.

New commands: force_sensor.pressed. New idea: a while True loop that keeps checking.

THE PROGRAM — TYPE THIS INTO THE SPIKE APP
# magic header (from memory) + pair line
# ...
async def main():
    while True:
        if force_sensor.pressed(port.D):
            motor_pair.move(motor_pair.PAIR_1, 0, velocity=300)
        else:
            motor_pair.stop(motor_pair.PAIR_1)
        await runloop.sleep_ms(50)

runloop.run(main())
  • force_sensor.pressed(port.D) — True while the button is pressed, False when released.
  • while True: — check again and again, forever (until you stop the program).
  • await runloop.sleep_ms(50) inside the loop — a tiny rest so the hub can breathe between checks. Always put a short sleep inside a while True loop.
✍️ WRITE — Hand-copy the loop.

▶️ RUN — Try it. Press, release, press.

MISSION 7 — Loops & Decisions

Goal: Count your button presses and show the count on the lights.

New idea: waiting for press AND release so one press counts exactly once. (You know variables from Python!)

THE PROGRAM — TYPE THIS INTO THE SPIKE APP
# magic header (from memory) — no pair line needed today
# ...
def is_pressed():
    return force_sensor.pressed(port.D)

def is_released():
    return not force_sensor.pressed(port.D)

async def main():
    count = 0
    await light_matrix.write('0')
    while True:
        await runloop.until(is_pressed)    # wait for press...
        await runloop.until(is_released)   # ...and release (one press = one count!)
        count = count + 1
        await light_matrix.write(str(count))

runloop.run(main())
  • await runloop.until(is_pressed) — until accepts a helper function (no lambda needed). Clean and readable — this is the official LEGO style.
  • Why wait for the release too? Without it, one long press would count dozens of times. Press + release = exactly one count.
  • str(count) — write() needs text, so the number becomes a string first. (You know str() from Python!)
✍️ WRITE — Hand-copy the two helpers and the loop.
🔮 PREDICT — Press 3 times, quickly. What shows? Now hold one press for 5 seconds — what shows, and why?
▶️ RUN — Try both. Was the release-wait the reason?
🚀 EXTEND — Play a sound every time the count hits a multiple of 5. Hint: count % 5 == 0 — you know % from Python!

Goal: Teach the robot turn_left() and turn_right(), then drive a square in 4 lines.

New idea: async functions — async def + await when you call them.

THE PROGRAM — TYPE THIS INTO THE SPIKE APP
# magic header (from memory) + pair line
# ...
async def turn_right():
    motion_sensor.reset_yaw(0)
    motor_pair.move(motor_pair.PAIR_1, 100, velocity=200)
    await runloop.until(lambda: motion_sensor.tilt_angles()[0] <= -900)
    motor_pair.stop(motor_pair.PAIR_1)

async def turn_left():
    motion_sensor.reset_yaw(0)

🚀 MINI-PROJECT 3 — Simon Says

Goal: Build a memory game that runs entirely on the hub.

New commands: random.choice. New ideas: lists and return (both from Python!).

THE PROGRAM — TYPE THIS INTO THE SPIKE APP
# magic header (from memory) — no pair line needed today
from hub import port, light_matrix, motion_sensor
from app import sound
import runloop
import motor_pair
import color_sensor
import color
import distance_sensor
import force_sensor
import random

MOVES = ['A', 'B']   # A = short press, B = long press

def pressed():
    return force_sensor.pressed(port.D)

async def show_move(move):
    await light_matrix.write(move)
    await sound.play('Sport Whistle 1')
    await runloop.sleep_ms(400)

async def read_move():
    await runloop.until(pressed)
    await runloop.sleep_ms(300)
    if pressed():                                # still holding after 300 ms?
        await runloop.until(lambda: not pressed())
        return 'B'                               # long press!
    return 'A'                                   # short press

async def main():
    pattern = []
    for round in range(5):
        pattern.append(random.choice(MOVES))
        for move in pattern:                     # show the pattern...
            await show_move(move)
        await light_matrix.write('?')            # ...now YOUR turn
        for move in pattern:                     # read your answer...
            if await read_move() != move:
                await light_matrix.write('X')    # wrong!
                await sound.play('Male Jump 1')
                return
        await sound.play('Sport Whistle 2')      # round passed!
    await light_matrix.write('WIN')

runloop.run(main())
  • import random + random.choice(MOVES) — picks 'A' or 'B' at random. pattern.append(...) grows the list every round — lists, just like Python turtle!
  • return 'B' — a function can send an answer back. await read_move() becomes 'A' or 'B'.
  • return with nothing after it (in main) means "game over, stop the program."
  • How it plays: the hub flashes a pattern of A/B. You repeat it: short press = A, long press = B. Each round adds one step.
  • Steps: hand-write read_move(), predict what a long press returns, play, fix.
  • Done when: you can survive 5 rounds.
  • EXTEND: make each round faster (shrink the 400 ms pause as round grows), or add a third move 'C' = double-press.

MISSION 9 — Follow the Line

Goal: Make the robot follow your black tape line all by itself.

New commands: color_sensor.reflection. New idea: steer a little, check, steer again — hundreds of times per second.

THE PROGRAM — TYPE THIS INTO THE SPIKE APP
# magic header (from memory) + pair line
# ...
async def main():
    while True:
        if color_sensor.reflection(port.F) < 50:
            motor_pair.move(motor_pair.PAIR_1, -40, velocity=250)
        else:
            motor_pair.move(motor_pair.PAIR_1, 40, velocity=250)
        await runloop.sleep_ms(10)

runloop.run(main())
  • color_sensor.reflection(port.F) — how much light bounces back: 0 (black) to 100 (white). Below 50 ≈ "I'm on the black line."
  • The loop's logic: on black → steer left a little; on white → steer right a little. The robot wiggles along the edge of the line — that wiggle IS line following.
  • await runloop.sleep_ms(10) — check the sensor 100 times per second.
✍️ WRITE — Hand-copy the loop (4 lines).

💡 Drives AWAY from the line? Your sensor sits on the other side — just swap the two steering numbers (-40 ↔ 40). One change, then test.
MISSION 10 — Drive Arrow-Straight

Goal: Drive perfectly straight by letting the gyro fix the steering 50 times per second.

New idea: correction — if the robot drifts a little left, steer a little right. Automatically. Forever.

THE PROGRAM — TYPE THIS INTO THE SPIKE APP
# magic header (from memory) + pair line
# ...
async def drive_straight(seconds):
    motion_sensor.reset_yaw(0)
    for _ in range(seconds * 50):
        drift = motion_sensor.tilt_angles()[0]  # tenths of a degree off course
        steering = drift // 10                  # small drift -> small correction
        if steering > 100:
            steering = 100
        if steering < -100:
            steering = -100
        motor_pair.move(motor_pair.PAIR_1, steering, velocity=300)
        await runloop.sleep_ms(20)
    motor_pair.stop(motor_pair.PAIR_1)

async def main():
    await drive_straight(3)

runloop.run(main())
  • drift = motion_sensor.tilt_angles()[0] — how far the robot has turned away from straight, in tenths of a degree. Positive = drifted left, negative = drifted right.
  • steering = drift // 10 — turn the drift into a steering correction: drifted 5° left (50) → steer 5 right. The fix is proportional to the mistake. (This idea even has a grown-up name: proportional control.)
  • The if lines keep steering inside -100…100 so the motors never get an impossible command.
  • for _ in range(seconds * 50) — 50 corrections per second, for seconds seconds. await drive_straight(3) drives straight for 3 seconds.
✍️ WRITE — Hand-copy drive_straight().
🔮 PREDICT — Why should this drive straighter than Mission 3's move_for_degrees? What would happen if the correction used drift directly instead of drift // 10?
▶️ RUN — Mark a start line with tape. Drive 3 seconds. Measure how far sideways it drifted.
🚀 EXTEND — Race: Mission 3's square vs. a square built with drive_straight + turn_right(). Which one ends closer to the start? Then try drive_straight(5) — does a longer run drift more?

Troubleshooting — When Something Goes Wrong

  • NameError: name '...' is not defined — a line from the magic header is missing. Compare your header with this guide, letter by letter.
  • Nothing happens when you press run — did you forget the last line, runloop.run(main())? Without it, the program never starts.
  • Robot skips a step instantly — you forgot await in front of it. Every step that takes time needs await.
  • Robot drives backward? Change velocity=300 to velocity=-300. One change, then test.
  • Robot turns the wrong way? Swap the steering sign (100 ↔ -100) in that turn.
  • TypeError with the distance sensor? You compared None with a number — use the d is not None and ... pattern from Mission 4.
  • Sensor sees nothing? Is the cable in the same port letter the code uses? (A = left motor, E = right motor, C = distance, F = color, D = force.)
  • Line follower drives AWAY from the line? Swap the two steering numbers (-40 ↔ 40).
  • Red error message? Read it! It tells you the exact line number. Go to that line.
  • Hub won't connect? Charge the battery, then restart the app.
  • Golden rule, always: change ONE thing at a time, then test.
